# Architecture

How the project is actually put together, as of 2026-09-12.

---

## Shape of the system

Two products share one data source. Nothing is a service; there is no backend,
no database and no runtime API.

```
  Proctor Schedule by Date.xlsm          <-- data source of truth (OneDrive)
  ├── Exam sheet ........... assignments the committee edits
  ├── Proctors sheet ....... the roster
  ├── Emails sheet ......... name -> address, entered by hand
  ├── Room Plan sheet ...... generated by VBA from Exam
  ├── Reminders sheet ...... generated by VBA from Exam + Emails
  └── Message sheet ........ email wording, edited as cells
            │
            ├──────────────► VBA (mReminders) ──► classic Outlook ──► staff inbox
            │
            └──► build.py ──► data.json
                          └─► index.html      ──► git push ──► Actions ──► Pages
                          └─► artifact.html   ──► Claude artifact (private copy)
```

The two halves are joined only by the workbook and by one shared rule: **the
first proctor listed takes the first room listed**. The website, the Room Plan
sheet and the reminder emails all apply it independently, so they agree.

---

## The website build

`build.py` is a one-shot generator. It:

1. Copies the workbook to a temp file first, so it can be read while open in
   Excel (Excel denies direct reads).
2. Reads the `Exam` sheet (header row 5, data from row 6) and the `Proctors`
   sheet (column A from row 6).
3. Drops exams before `WINDOW_START` (`2026-09-03`).
4. Rejects any Date cell that is not `yyyy-mm-dd`, empties it, and reports the
   row.
5. Recomputes each exam's shortfall from the filled `Proctor 1..10` cells,
   ignoring the workbook's own `Still Needed` column, whose formulas are broken
   on several rows.
6. Pairs proctors with rooms positionally; leftover rooms become `spareRooms`.
7. Writes `data.json`, then injects that JSON into `template.html` at the
   `/*__DATA__*/ null` placeholder to produce `index.html` (wrapped in a full
   HTML document) and `artifact.html` (the same body, unwrapped).

The page is entirely self-contained — the data is baked in, so it works from
disk, over email, or from a USB stick with no server.

## Deployment

`sync.cmd` is the whole release process: rebuild, `git add -A`, commit, push.
A GitHub Actions workflow then publishes the repo root to Pages. The build
never runs in CI, because the workbook is not in the repo.

## The reminder system

VBA lives in one standard module (`mReminders`) plus the `Reminders` sheet's
own event code. `update_vba.py` replaces that code inside the existing `.xlsm`
without touching any sheet, which is what keeps hand-entered data safe.

Outlook is reached over COM. The fragile part is acquiring it: if Outlook is
not already running, `CreateObject` starts it with no window, where it waits on
a sign-in prompt it cannot draw and every call blocks forever. `GetOutlook`
therefore logs the MAPI session on explicitly and opens an Explorer window if
none exists.

## Data contract

`data.json` and the injected page data share one shape. Each exam carries:

`date` `day` `start` `end` `time` `course` `coordinator` `dept` `room`
`rooms[]` `assignments[{name, room}]` `spareRooms[]` `students` `required`
`assigned` `shortfall` `proctors[]` `sourceRow`

Plus top level: `generatedAt` `sourceFile` `sourceModified` `windowStart`
`summary{}` `proctorIndex[]` `courseIndex[]`.

`sourceRow` maps a page row back to its workbook row, which is how a bad cell
gets reported precisely.

## Known architectural weak points

- **Positional room pairing is a convention, not a constraint.** If the
  committee ever writes rooms in a different order from proctors, every
  downstream view is silently wrong. Verified against the committee's own PDF,
  but nothing enforces it.
- **No test suite.** Verification is manual: run the build, load the page,
  check the console.
- **`WINDOW_START` is hardcoded** to `2026-09-03`. A new exam period needs it
  changed (it is overridable by environment variable).
- **Generated files are committed.** Necessary, because Pages serves the repo
  and CI cannot rebuild, but it means `git diff` is noisy on every refresh.
